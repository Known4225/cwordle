# cwordle

Here's the idea: Levenshtein edit distance.

It's much easier to remember a large amount of words if there is a simple way to move between them. Ideas include chains, trees, graphs.

The first step is to collect data on what you're most likely to see when guessing yesterdays word as the first word for today. Then using that data along with swordle, I'll construct the best possible guesses and string them together into a chain.

# Chain creation algorithm ideas

I'm thinking construct a big tree. Start with a word (input to a function) and then generate a tree from that word. Each level is +1 edit distance from a parent. Sorted left to right as best to worst. Ensure that children do not have their parent as their child (avoid recursive graph).

Visualise and allow cursor to highlight a chain, which goes from cursor position up the tree to the root word. Calculate the score of the chain by adding up the scores of all the words in the chain.

I would also like to calculate the coverage of a chain. This might be difficult though.

# Coverage

Coverage refers to how often a word is to be a valid second guess after using yesterday's word as your first guess. In this case a valid second guess means that it must be possible that the answer is this word given the information we have. So you could rephrase it to say that QAJAQ is still on the table 16.4170% of the time after using yesterday's word as your first guess. Of course in reality the actual word will never be QAJAQ, but we allow all words to be searched because they could provide us with the most information even if they themselves cannot be the answer to the wordle. Obviously this is not the case for QAJAQ.

SIDER -> CIDER

Sometimes this is because you have to, other times it's because you would get additional information. The idea of having a platonic ideal of a word (such as ROATE or TIARE) and then many ways to mold it, changing one letter or two, is very powerful.
